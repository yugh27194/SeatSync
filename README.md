# SeatSync Web

공공도서관 열람실의 **예약 정보**와 카메라가 감지한 **실제 착석 상태**를 대조해
사석화(짐만 두고 장시간 이석)와 무단 사용(미예약 착석)을 관리자 화면에 표시하는 웹 서버.
시스템은 표시만 하고, 제재·조치는 관리자가 결정한다.

- 명세: [SEATSYNC_WEB_SPEC.md](SEATSYNC_WEB_SPEC.md)
- 스택: Python 3.10+, Flask, SQLite(`sqlite3`), Jinja, 바닐라 JS, 순수 CSS

```
[Pi: 카메라 → YOLO → 좌석 매핑] --POST /api/detections (5초마다)--> [Flask: judge() + SQLite]
                                                                     ├─ 사용자 화면 (/map, /seat/<no>, /my)   ← 3초 polling
                                                                     └─ 관리자 화면 (/admin, /admin/settings) ← 3초 polling
```

## 실행 방법

```
pip install -r requirements.txt
flask --app app init-db            # 스키마 생성 + seed (--reset: DB 삭제 후 재생성)
python app.py                      # 0.0.0.0:5000, threaded
```

폰·Pi는 노트북과 같은 Wi-Fi(또는 휴대폰 핫스팟)에서 `http://<노트북IP>:5000` 으로 접속한다.

| 계정 | 비밀번호 | 역할 |
|---|---|---|
| `admin` | `admin1234` | 관리자 → `/admin` |
| `userA` / `userB` / `userC` | `1234` | 사용자A·B·C → `/map` |
| `20260001` ~ `20260005` | `1234` | 사용자(테스트1~5) → `/map` |

> DB 구조가 바뀌었습니다. 이전 버전 DB가 있다면 `flask --app app init-db --reset` 으로 다시 만드세요.

| 이름 | 기본값 | 설명 |
|---|---|---|

## 좌석 상태와 예약 대조

좌석 상태는 **빈자리 / 예약(사용중) / 사용불가** 세 가지만 쓴다. 이용자 화면에는 이 세 가지만 보인다.

관리자 화면은 **예약 기록**과 **현장 상태**를 대조해 조치가 필요한 좌석을 ⚠로 표시한다.
현장 상태는 카메라 연동 전까지 관리자가 좌석별로 **임시 배분**한다(좌석 상세의 [빈자리|사용중|사용불가] 버튼).
초기값은 `config/seats.json`의 `state`(`empty|occupied|unavailable`)·`note` 로 정한다.

| 예약 기록 \ 현장 | 빈자리 | 사용중 | 사용불가 |
|---|---|---|---|
| 없음 | 빈자리 · 정상 | 예약(사용중) · ⚠ **미예약 사용** | 사용불가 · 정상 |
| 예약(입실 전) | 예약(사용중) · 정상(입실 대기) | 예약(사용중) · ⚠ **체크인 누락** | 사용불가 · ⚠ **예약 좌석 사용불가** |
| 이용 중 | 예약(사용중) · 정상(잠시 자리 비움) → 허용 시간 초과 시 ⚠ **장시간 자리 비움** | 예약(사용중) · 정상 | 사용불가 · ⚠ **예약 좌석 사용불가** |

체크인 제한 시간을 넘긴 예약은 자동으로 **미입실** 처리되고 알림이 남는다.

### 상황별 관리자 조치

| 상황 | 권장 조치 |
|---|---|
| 미예약 사용 | **현장 배정**(앉아 있는 이용자에게 좌석 배정) · **퇴실 안내 완료**(현장 상태 → 빈자리) |
| 체크인 누락 | **대리 체크인**(본인 확인 시) · **예약자 다른 좌석으로 이동**(다른 사람이 앉아 있을 때) |
| 장시간 자리 비움 | **강제 반납** · **예약자 경고** |
| 예약 좌석 사용불가 | **다른 좌석으로 이동** · **예약 취소** |
| 미입실 | **경고 후 확인** · 확인 |
| 이용자 호출 | 좌석 보기 → 상황에 맞게 조치 · 처리 완료 |

그 밖에 좌석마다 대리 예약·배정, 좌석 이동, 관리자 연장, 강제 반납, 경고를 할 수 있다.

- **이용자 관리**: 경고 부여·취소, 이용 정지(기간 지정)·해제. 경고가 기준 횟수(기본 3회) 이상이면 정지를 권장한다. 정지된 이용자는 새 예약을 할 수 없다.
- **처리 이력**: 모든 관리자 조치(누가·언제·어느 좌석·누구에게·사유)가 기록된다.
- **시연 상황 배치**: 관리자 화면의 버튼(또는 `flask --app app demo`)으로 아래 상황을 한 번에 만든다.

| 좌석 | 예약 | 현장 | 결과 |
|---|---|---|---|
| A-1 | 사용자A 이용 중 | 사용중 | 정상 |
| A-2 | 사용자B 이용 중 | 40분째 빈자리 | 장시간 자리 비움 |
| A-3 | 없음 | 사용중 | 미예약 사용 |
| A-4 | 사용자C 예약(입실 전) | 사용중 | 체크인 누락 |
| B-1 | 없음 | 사용불가(의자 파손) | 사용불가 |
| B-2 | 테스트1 예약 | 사용불가(조명 고장) | 예약 좌석 사용불가 |
| B-3 | 테스트2 이용 중 | 5분째 빈자리 | 정상(잠시 자리 비움) |
| B-4 | 테스트3 예약 후 미입실 | 빈자리 | 미입실 → 자동 취소, 빈자리 |

### 좌석 배치

`config/seats.json`을 수정한 뒤 `flask --app app init-db`를 다시 실행하면 좌석이 갱신된다(`qr_token`과 현장 상태는 유지,
빠진 좌석은 비활성 처리). 좌석 번호 `no`는 Pi 매핑과 공유하는 유일한 키다.

### 좌석 QR 만들기

```
python tools/make_qr.py --base-url http://<노트북IP>:5000   # qr/seat_<no>.png + qr/print.html (A4 인쇄용)
```

### 개발 도구 · 테스트

```
python tools/simulate.py --url http://localhost:5000 --key dev-key   # 대화형 가짜 감지 (set 3 person / set 5 item -40m / all empty / show)
python tools/simulate.py --scenario demo                             # 정상 이용·사석화·무단 사용·미입실 시나리오 자동 재생
python -m pytest -q
```

시연 전 `/admin/settings` → [시연 모드] → [저장]으로 기준 시간을 짧게(자리 비움 허용 1분 등) 바꿔 두면 빠르게 확인할 수 있다.
시뮬레이터는 카메라처럼 모든 좌석의 현장 상태를 덮어쓰므로, 관리자가 현장 상태를 직접 배분하는 동안에는 실행하지 않는다.

## Pi → 웹 계약 (요약)

`POST /api/detections` · 헤더 `X-Device-Key` · 5초마다 전체 좌석 전송

```json
{ "camera_id": "cam1", "ts": "2026-09-30T14:03:12+09:00",
  "seats": [ { "seat_no": 1, "occupancy": "person", "since": "2026-09-30T13:40:02+09:00", "confidence": 0.87 } ] }
```

- `occupancy`: `person | item | empty` (Pi에서 필터링을 마친 확정값) → 현장 상태 `사용중`(person·item) / `빈자리`(empty)
- 관리자가 `사용불가`로 지정한 좌석은 카메라가 덮어쓰지 않는다
- 서버-Pi 시계 차이가 5초를 넘으면 `since`를 서버 시각 기준으로 보정
- 알 수 없는 좌석 번호는 무시하고 응답 `ignored`에 담는다
- 서버는 영상·이미지를 받거나 저장하지 않는다 — 좌석 번호와 점유 상태만 받는다

### 명세 해석 메모 (`# SPEC-ASSUMPTION:` 주석 참고)

- 기존 명세의 12단계 판정은 3상태 + 대조 결과(정상/⚠ 5가지)로 단순화했다.
- 예약 없이 앉아 있는 좌석은 이용자에게 '예약(사용중)'으로 보인다(대조 결과는 관리자에게만 표시).
- 좌석 QR 체크인은 본인이 앉아 있다는 뜻이므로 현장 상태를 '사용중'으로, 반납은 '빈자리'로 바꾼다(카메라가 있으면 다음 감지로 바로잡힘).
- 알림은 해당 상황으로 **전이할 때만** 생성한다 — 처리 완료한 뒤 같은 상황이 이어져도 다시 뜨지 않는다.
- 관리자 연장은 연장 가능 시점·횟수 제한을 적용하지 않고, 이용자 연장 횟수에도 포함하지 않는다.
- 자리 비움 비율 = 장시간 자리 비움 / (정상 이용 + 장시간 자리 비움).
