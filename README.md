# SeatSync — 열람실 좌석 예약 × 실제 이용 대조 서비스

[![tests](https://github.com/yugh27194/SeatSync/actions/workflows/tests.yml/badge.svg)](https://github.com/yugh27194/SeatSync/actions/workflows/tests.yml)

공공도서관·스터디카페 열람실에서 **예약 기록**과 카메라가 감지한 **실제 착석 상태**를 대조해,
사석화(짐만 두고 장시간 이석)·장기 이석·무단 점유(QR 체크인 없이 사용) 같은 문제 좌석을 찾아 관리자에게 알리고,
이용자에게는 예약·체크인·빈자리 알림·사전 경고를 제공하는 **Django 기반 웹서비스**입니다.

**소개 페이지: https://seatsync-skku.github.io** · 서비스 바로가기: https://seatsync-skku.github.io/go/

> 시스템은 **표시하고 알릴 뿐**, 제재·조치는 관리자가 결정합니다. 영상·얼굴 데이터는 저장하지 않습니다.

---

## 1. 기획

### 문제
- 예약 시스템에는 "예약됨"으로 나오지만 실제로는 **짐만 두고 몇 시간째 비어 있는 자리**(사석화)가 많다.
- 반대로 **예약 없이 앉아 있는 사람**(무단 점유) 때문에 예약한 사람이 자리를 쓰지 못한다.
- 관리자는 열람실을 계속 돌아보지 않는 한 어느 자리가 문제인지 알기 어렵다.

### 목표
1. 예약 정보와 실제 좌석 상태를 **자동으로 대조**해 문제 좌석을 좌석 단위로 표시한다.
2. 이용자가 **폰만으로** 예약·체크인(좌석 QR)·연장·반납할 수 있게 한다.
3. 문제가 되기 **전에 본인에게 사전 경고**하고, 관리자는 상황에 맞는 조치를 버튼으로 처리한다.
4. 혼잡도·실사용률을 측정해 운영 판단에 쓴다.

### 설계 원칙
- **개인정보 최소화**: 카메라 영상은 라즈베리파이 안에서만 처리하고, 웹은 좌석 번호와 상태만 받는다. 얼굴 인식·녹화 없음.
- **판정 로직은 순수 함수**(`judge()`): DB·시각에 의존하지 않아 모든 경우를 테스트로 검증한다.
- **기준값은 코드에 고정하지 않음**: 좌석 배치는 `config/seats.json`, 시간 기준은 관리자 설정 화면.
- **모바일(360px) 우선**: QR을 찍으면 폰 브라우저로 바로 열린다.
- **판단 불가는 빈자리가 아니다**: 카메라가 판단하지 못하면 마지막 상태를 유지하고 시간 기반 판정을 보류하다가,
  기준 시간이 지나면 **관리자 확인(! 판단 불가)** 으로 넘긴다.
- **관리자는 예외만 확인**: 명확한 경우는 자동 반영하고, 애매하거나 QR 체크인과 카메라 감지가 어긋날 때만 관리자 확인 목록에 올린다.

### 시스템 구성

```mermaid
flowchart LR
  subgraph PI["라즈베리파이 (카메라)"]
    C["카메라"] --> M["seat_monitor<br/>YOLO11n 사람 감지<br/>좌석 ROI 배정"] --> S[("status.json")] --> B["pi_bridge.py"]
  end
  B -- "HTTPS · 좌석 상태만" --> W
  subgraph W["SeatSync 웹 (Django + SQLite)"]
    D["감지 수신"] --> R["refresh: 예약 × 현장 대조<br/>judge() → 좌석 상태·처리 필요"]
    R --> N["알림 · 사전 경고 · 빈자리 안내 · 통계"]
  end
  W --> U["이용자 (폰)<br/>지도 · QR 체크인 · 내 기록"]
```

- 카메라 연동 전이나 카메라가 없는 좌석은 관리자가 좌석 상태를 **임시로 부여**해 운영할 수 있다.

## 2. 좌석 상태와 판정

**판정 흐름** — 시스템이 1차로 자동 판정하고, 관리자는 예외만 최종 확인한다.

```mermaid
flowchart LR
  Q["좌석별 QR 체크인<br/>(A-1 QR → A-1 좌석)"] --> C{"비교"}
  K["카메라 사람 감지<br/>OCCUPIED · EMPTY · UNKNOWN"] --> C
  C -->|명확| A["자동 반영<br/>정상 이용 · 일시 이석 · 빈자리"]
  C -->|"기준 시간 초과·충돌·판단 불가"| M["! 관리자 확인 필요<br/>장기 이석 · 무단 점유 · 판단 불가 …"]
```

**좌석 판단 기준** (QR 체크인 × 카메라 감지)

| 판정 | QR 체크인 | 카메라 | 처리 |
|---|---|---|---|
| **정상 이용** | 함 | 사람 감지 | 자동 반영 |
| **일시 이석** | 함 | 사람 미감지 (장기 이석 기준 전) | 자동 반영 · 기준 10분 전 본인 사전 경고 |
| **! 장기 이석** | 함 | 사람 미감지가 **장기 이석 기준(30분)** 이상 | 관리자 확인 · 본인 알림 · 15분 뒤 자동 반납 |
| 착석 감지 | 안 함 | 사람 감지 (무단 점유 기준 전) | 자동 반영 (체크인 기다림) |
| **! 무단 점유** | 안 함 | 사람(또는 짐)이 **무단 점유 기준(10분)** 이상 | 관리자 확인 (예약석이면 ! 체크인 누락) |
| **! 판단 불가** | — | 가림·인식 실패·카메라 오류(`UNKNOWN`)가 **판단 불가 기준(3분)** 이상 | 관리자 확인 → 현장을 보고 실제 상태 지정 |

- 판단 불가인 동안에는 마지막으로 확인된 상태를 보여 주고, 장기 이석·무단 점유 기준 시간을 세지 않는다(감지 끊김 ≠ 자리 비움).
  끊기기 전에 이미 확인 필요였던 판정은 그대로 둔다.
- 기준 시간은 **설정** 탭에서 15초 단위로 바꾼다. **[시연 모드]**: 장기 이석·무단 점유 30초, 판단 불가 15초 (3분 시연용).

좌석 상태는 **빈자리 / 사용중 / 사용불가** 세 가지이고, 각각 세부 상태를 가진다.

**관리자 탭의 상태 분류 (4가지)**

| 색 | 분류 | 세부 상태 |
|---|---|---|
| 🟩 초록 | **정상** | 정상 이용 · 빈자리 · 입실 대기 · 착석 감지/착석(체크인 전, 기준 시간 전) |
| 🟧 주황 | **이석** — 일시 / 장기 | 일시: 일시 이석 · 짐만 있음 / 장기: ! 장기 이석 · ! 사석화 · ! 미입실 |
| 🟥 빨강 | **무단 점유** | ! 무단 점유 · ! 체크인 누락 |
| ⬛ 짙은 회색 | **판단 불가** | ! 판단 불가 (카메라 인식 오류 — 관리자 확인) |

- 빨간 `!` = 관리자 확인이 필요한 좌석(조치 목록에 오름). 고장·점검 등 사용불가 좌석은 옅은 회색 빗금.
- 이용자 좌석 지도는 예약에 필요한 3색만 쓴다: 🟩 빈자리 · 🟧 사용중 · ⬜ 사용불가 (관리자 표시는 관리자 탭에만).

세부 상태 (`!` = 관리자 확인 목록에 오르는 상태)

| 좌석 상태 | 세부 상태 |
|---|---|
| **빈자리** | 빈자리 |
| **사용중** | 정상 이용 · 입실 대기 · 착석 감지(체크인 전) · 착석(체크인 전) · 일시 이석 · **짐만 있음** · ! 무단 점유 · ! 체크인 누락 · ! 미입실 · ! 장기 이석 · ! 사석화 · ! 판단 불가 |
| **사용불가** | 고장 · 점검·청소 · 사용 중지 · ! 예약 좌석 사용불가 |

**예약 × 현장 대조 규칙** (U = 무단 점유 기준 10분)

| 예약 \ 현장 | 비어 있음 | 사람 있음 | 짐만 있음 |
|---|---|---|---|
| 없음 | 빈자리 | 착석 감지 → U 초과 **! 무단 점유** (관리자 확인 시 정상 이용) | 짐만 있음 → U 초과 **! 무단 점유** |
| 입실 전 | 입실 대기 → 15분 초과 **! 미입실** | 착석(체크인 전) → U 초과 **! 체크인 누락** | 착석(체크인 전) → U 초과 **! 체크인 누락** |
| 이용 중 (QR 체크인) | 일시 이석 → 30분 초과 **! 장기 이석** | 정상 이용 | 짐만 있음 → 30분 초과 **! 사석화** |

- 예약 좌석이 사용불가가 되면 ! 예약 좌석 사용불가. 미입실은 늦게 와도 본인 체크인 가능.
- 미입실·장기 이석·사석화가 **자동 강제 반납** 시간(기본 15분) 넘게 이어지면 예약을 자동으로 반납·취소한다(설정에서 변경, 0 = 끔).
- 자리 비움 시간은 체크인 이후부터 센다.

**운영 기준값 (기본값, 관리자 화면에서 변경)**

| 항목 | 기본값 | 항목 | 기본값 |
|---|---|---|---|
| 체크인 제한 | 15분 | 기본 이용 시간 | 120분 |
| 장기 이석 기준 | 30분 | 연장 | 60분씩, 종료 30분 전부터, 최대 2회 |
| 사석화 기준 | 30분 | 사전 경고 시점 | 기준 10분 전 |
| 무단 점유 기준 | 10분 | 판단 불가 기준 | 3분 |
| 자동 강제 반납 | 확인 필요 후 15분 | 빈자리 안내 유지 | 5분 |
| 정지 권장 경고 수 · 기본 정지 기간 | 3회 · 3일 | | |

## 3. 주요 기능

| 이용자 | 관리자 (**[관리자] 탭**) |
|---|---|
| 8석 **좌석 지도**에서 예약, 지금 혼잡도 | 4가지 상태 분류(정상·이석·무단 점유·판단 불가) 색 + `!`, 좌석별 상태 설명·처리 방법, **조치 목록** |
| **좌석 QR** 체크인·바로 예약 (원격 체크인 방지 토큰) | 좌석 상태 지정(빈자리·예약·사용중·사용불가), 판단 불가 좌석 **현장 확인** |
| 연장·반납·관리자 호출, 남은 시간 카운트다운 | 상황별 조치: 현장 배정·퇴실 안내·대리 체크인·좌석 이동·강제 반납·짐 수거 |
| **빈자리 알림 대기** (구역 선택, 5분 우선 예약) | **예약 대조·카메라** 한 표, 처리 이력(누가·언제·무엇을) |
| **내 이용 기록**: 일/주/월 이용 시간, 연장·반납 이력 | 좌석을 누르면 **상태 설명·처리 방법**과 조치 버튼 |
| **혼잡도 히트맵** (요일×시간) | 이용자 **사전 경고·경고·이용 정지** |
| 🔔 **사전 경고**·처리 필요 전환·빈자리 안내 알림 | **이용 분석**(실사용률·유휴 점유·처리 필요), **판정 기준** 설정 |
| | **좌석 QR 보관함**: 좌석에 붙여 둔 QR을 그대로 A4 한 장으로 보고 인쇄 (새로 만들거나 바꾸지 않음) |

- 관리자 계정은 따로 없다. 관리자 개입이 필요한 기능은 모두 **[관리자] 탭**에만 있다.
  탭을 처음 누르면 팝업으로 관리자 코드를 묻고, 맞으면 들어간다. 같은 로그인(세션) 동안에는 다른 탭에 다녀와도 다시 묻지 않는다.
- 관리자 탭 메뉴: **대시보드 · 좌석 QR · 이용 분석 · 판정 기준**.
- 자세한 기능 설명: [docs/FEATURES.md](docs/FEATURES.md)

## 4. 구현 요약

- **Django 5.2 + SQLite**, Django 템플릿 + 바닐라 JS(3초 polling), 순수 CSS. 빌드 도구 없음.
- 모든 요청마다 한 트랜잭션에서 `refresh()` 파이프라인 실행: 예약 종료 정리 → 전 좌석 `judge()` → 전이 기록 → 처리 필요 알림(전이 시 생성·자동 해소) → 본인 사전 경고 → 빈자리 안내.
- 동시 예약은 SQLite `BEGIN IMMEDIATE` + 활성 예약 유일 제약으로 하나만 성공.
- 보안: Django 인증·CSRF, 좌석 QR 토큰 상수 시간 비교, 관리자 코드 5회 실패 시 잠금, 디바이스 키.
- 라즈베리파이 감지 프로토타입의 `status.json`(schema_version 1)을 그대로 받는 수신기와 Pi용 브리지(`tools/pi_bridge.py`).
- 테스트 166개(pytest), GitHub Actions에서 실행.

## 5. 실행

```bat
python -m venv .venv
.venv\Scripts\activate                     :: macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python manage.py init_db                   :: DB 생성 + 좌석 8석·설정·테스트 계정
python manage.py runserver 0.0.0.0:5000
```

브라우저: `http://localhost:5000` · 같은 Wi-Fi의 폰: `http://<PC의 IP>:5000`

| 계정 | 비밀번호 | 관리자 코드 |
|---|---|---|
| `userA` / `userB` / `userC`, `20260001`~`20260005` | `1234` | `admin` (환경변수 `SEATSYNC_ADMIN_CODE`로 변경) |

| 명령 | 설명 |
|---|---|
| `python manage.py init_db --sample` | 서버를 처음 만들 때: DB 준비 + **시연용 샘플 한 번만**(지난 4주 이용 기록 + 시연 상황). 이미 만들었으면 건너뜀 |
| `python manage.py serve` | 외부 공유용 서버(waitress)로 실행 |
| `python manage.py init_db --reset` | DB를 지우고 새로 만들기 (좌석 QR 토큰은 유지 — 출력해 둔 QR 그대로 사용) |
| `python -m pytest` | 테스트 |

시연 상황 배치·샘플 기록은 웹사이트에서 만들 수 없다(실제 기록과 섞이지 않게). 콘솔의 `demo`·`demo_history` 명령은 개발용으로만 남아 있다.

**외부 링크로 공유**: `share.bat` 실행 → `https://….trycloudflare.com` 주소 공유 / 상시 배포는 PythonAnywhere
(`bash deploy/pythonanywhere_setup.sh`), 소개 페이지는 GitHub Pages(`pages/`) — [docs/DEPLOY.md](docs/DEPLOY.md)

| `SEATSYNC_SECRET_KEY` | 개발용 값 | Django 세션·CSRF 서명 키 |
| `SEATSYNC_DEVICE_KEY` | `dev-key` | 라즈베리파이 인증 키 |
| `SEATSYNC_DB` | `seatsync.db` | SQLite 파일 경로 |
| `SEATSYNC_TZ` | `Asia/Seoul` | 표시용 타임존 |
| `SEATSYNC_TRUSTED_ORIGINS` | – | 외부 배포 주소 추가 허용(쉼표 구분) |
| `SEATSYNC_HTTPS` | `0` | HTTPS 전용 호스팅이면 `1` |

## 6. 좌석 배치 (8석)

`config/seats.json` — 실제 테스트용으로 **왼쪽 4석(2×2) · 오른쪽 4석(2×2)**, 카메라 1대(`cam1`)가 8석을 모두 본다.

```
 A-1  A-2    B-1  B-2
 A-3  A-4    B-3  B-4
```
지도에는 좌석만 표시한다(창문·통로·벽·출입문·안내데스크 표시 없음).

| 카메라 `cam1` calibrate 순서 | 웹 좌석 |
|---|---|
| A01 · A02 · A03 · A04 | 왼쪽 **A-1 · A-2 · A-3 · A-4** (윗줄 왼→오, 아랫줄 왼→오) |
| A05 · A06 · A07 · A08 | 오른쪽 **B-1 · B-2 · B-3 · B-4** (윗줄 왼→오, 아랫줄 왼→오) |

처음에는 8석 모두 빈자리로 시작한다. `"demo"` 목록은 서버를 처음 만들 때 `init_db --sample`로 한 번만 쓰인다
(A-1 정상 이용 · A-2 장기 이석 · A-3 무단 점유 · A-4 착석 감지 · B-1 짐만 있음 · B-2 사석화 · B-3 판단 불가 · B-4 고장).

좌석마다 번호(`no`), 라벨, 위치, 구역, 카메라 대응(`camera_id` + calibrate 순서 `camera_seat`), 초기 상태를 적는다.
배치를 바꾼 뒤 `python manage.py init_db`를 실행하면 반영된다(빠진 좌석은 비활성, 그 좌석의 진행 중 예약은 취소).
테스트는 예전 20석 배치(`tests/seats20.json`)로도 돌려 여러 구역·카메라 2대 상황을 계속 확인한다.
