# SeatSync Web (Django)

공공도서관·스터디카페 열람실의 **예약 정보**와 **실제 좌석 상태**를 대조해
무단 점유, 이탈, 사석화 같은 문제 좌석을 표시하고 관리자가 처리할 수 있게 하는 웹 서버.
시스템은 표시만 하고, 제재·조치는 관리자가 결정한다.

- 스택: Python 3.10+, **Django 5.2**, SQLite, Django 템플릿, 바닐라 JS, 순수 CSS
- 초기 명세: [SEATSYNC_WEB_SPEC.md](SEATSYNC_WEB_SPEC.md) (Flask 기준으로 작성됨 — 이후 요구에 맞게 개편)

## 실행 방법 (Windows cmd 기준)

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python manage.py init_db                    :: DB 생성 + 좌석·설정·테스트 계정 입력
python manage.py runserver 0.0.0.0:5000     :: 실행
```

- 브라우저: `http://localhost:5000`, 폰(같은 Wi-Fi): `http://<노트북IP>:5000`
- 구조가 바뀐 뒤 처음 실행하거나 전부 지우고 새로 시작할 때: `python manage.py init_db --reset`
- 시연 상황 한 번에 만들기: `python manage.py demo` (관리자 화면의 [시연 상황 배치] 버튼과 같음)
- 지난 4주 샘플 이력(내 기록·혼잡도 시연용): `python manage.py demo_history` (관리자 화면의 [샘플 이력 생성] 버튼과 같음)
- 이전 버전에서 업데이트했다면 `python manage.py migrate` 만 하면 된다(기존 데이터 유지).
- 테스트: `python -m pytest`

| 계정 | 비밀번호 |
|---|---|
| `userA` / `userB` / `userC` | `1234` (사용자A·B·C) |
| `20260001` ~ `20260005` | `1234` (테스트1~5) |

### 관리자 모드 (관리자 계정 없음)

로그인한 누구든 상단 **[관리자] 스위치**를 켜면 "관리자 권한이 필요합니다."가 표시되고,
**관리자 코드**(기본 `admin`)를 입력하면 관리자 모드가 켜진다. 스위치를 끄면 바로 일반 사용자 화면으로 돌아간다.

- 일반 사용자 화면에는 **`!`(처리 필요) 표시가 없다.** 관리자 모드에서만 좌석 지도에 `!`와 세부 상태가 보인다.
- 마지막 사용 후 60분이 지나거나 로그아웃하면 자동으로 꺼진다. 코드를 5번 틀리면 5분간 입력할 수 없다.
- 관리자 모드 켜기·끄기와 모든 조치는 **처리 이력**에 처리자(스위치를 켠 사용자)와 함께 남는다.

### 환경변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `SEATSYNC_ADMIN_CODE` | `admin` | 관리자 모드 코드 (**외부 공개 시 추측하기 어려운 값 권장**) |
| `SEATSYNC_ADMIN_MODE_MIN` | `60` | 관리자 모드 유지 시간(분, 마지막 사용 기준) |
| `SEATSYNC_SECRET_KEY` | 개발용 값 | Django 세션·CSRF 서명 키 (운영 시 변경) |
| `SEATSYNC_DEVICE_KEY` | `dev-key` | Pi 인증 키 (`X-Device-Key` 헤더) |
| `SEATSYNC_DB` | `seatsync.db` | SQLite 파일 경로 |
| `SEATSYNC_TZ` | `Asia/Seoul` | 표시용 타임존 |
| `SEATSYNC_DEBUG` | `0` | `1`이면 Django 디버그 화면 |
| `SEATSYNC_TRUSTED_ORIGINS` | (없음) | 외부 배포 주소 추가 허용 (쉼표 구분, 예: `https://seat.example.com`) |
| `SEATSYNC_HTTPS` | `0` | HTTPS 전용 호스팅이면 `1` (노트북 실행에서는 켜지 않음) |

cmd에서는 `set SEATSYNC_ADMIN_CODE=1357` 후 같은 창에서 `python manage.py runserver 0.0.0.0:5000`.

## 추가 기능

### 내 이용 기록
- 체크인부터 반납·종료까지 **실제 이용 시간**을 일별(14일)·주별(8주)·월별(6개월)로 집계한다. 자정을 넘긴 이용은 날짜별로 나눈다.
- 요약: 총 이용 시간, 평균, 예약 수, 최장 이용, 연장, 반납/시간 만료, 미입실·강제 반납.
- 예약마다 예약 → 체크인 → 연장(종료 시각 변화) → 반납 등 **이력 타임라인**과 받은 경고 기록.

### 혼잡도·실사용 측정
- **점유율**: 좌석이 사용중(예약·이용)인 비율. 모두 볼 수 있다.
- 관리자 모드 추가 지표: **실사용률**(사람이 실제로 앉아 있는 비율), **유휴 점유**(자리만 차지하고 비어 있는 비율 — 입실 대기·자리 비움·짐만 있음·이탈·사석화), **처리 필요** 비율, 예약 대비 실사용 비율.
- 좌석 상태 전이 이력(StatusLog)을 시간 단위로 나눠 계산하며, 운영 시간(기본 6~24시)은 설정에서 바꾼다.

### 빈자리 알림 대기
- 원하는 구역(또는 아무 자리)을 골라 대기 → 빈자리가 나면 **대기 순서대로 5분(설정) 동안 그 사람만 예약할 수 있게** 잡아 둔다.
- 안내 시간이 지나거나 [양보]하면 다음 대기자에게 넘어간다. 다른 사람에게는 그 좌석이 '대기자 안내 중'으로 보인다.

### 판정 피드백 (카메라 판정이 틀릴 때)
- 관리자가 좌석을 직접 확인하고 좌석 상세의 **[✓ 맞음] / [✗ 틀림]**을 누른다. 틀림이면 실제 상태를 골라 **바로 수정**하거나 기록만 남긴다.
- 전체·출처별(카메라/관리자 지정/QR 체크인 등)·상태별 **판정 정확도**와 자주 틀리는 판정(예: 무단 점유 → 실제 빈자리)을 보여 준다.

### 본인 계정 사전 경고
- 자리를 비움·짐만 두고 비움이 **이탈·사석화 기준 10분 전(설정)**이 되면, 체크인 마감 10분 전이면 본인에게 사전 경고 알림.
- 이탈·사석화·체크인 누락·예약 좌석 사용불가·내 예약석 다른 이용 확인 시 다시 알림. 같은 사안은 한 번만 보낸다.
- 관리자는 **[사전 경고]**(누적 경고에 포함되지 않는 주의 알림)와 **[경고(누적)]**를 구분해 보낼 수 있고, 경고·강제 반납·정지·해제도 본인에게 알림이 간다.
- 좌석 지도와 내 자리 화면에는 내 좌석 상태(예: "자리를 비운 상태예요. 8분 뒤 '이탈'로 처리됩니다")가 계속 표시된다.
- 휴대폰 푸시·문자는 범위 밖이다(웹 화면을 열어 두어야 알림이 뜬다). 예약 없이 앉은 사람은 누구인지 알 수 없어 본인 경고 대상이 아니다.

## 좌석 배치 (20석)

`config/seats.json` — 폰 화면(360px)에서도 좌석 칸이 56px 이상이 되도록 세로형 5열로 설계했다.

```
[          창   문          ]
 A-1  A-2  A-3  A-4  A-5        창가 1인석
 B-1  B-2   ┆   C-1  C-2
 [테이블]    통   [테이블]         4인 테이블 ×2 (마주 보는 좌석)
 B-3  B-4   로   C-3  C-4
 D-1  D-2   ┆   D-3  D-4        칸막이 1인 집중석
 E-1  E-2  E-3  [ 사물함 ]       노트북석(콘센트)
[벽·콘센트]
[출입문]          [안내데스크]
```

좌석 번호 `no`(1~20)는 Pi 매핑과 공유하는 키다. 좌석을 바꾼 뒤 `python manage.py init_db`를 다시 실행하면
좌석 정보가 갱신된다(QR 토큰·현재 상태는 유지, 빠진 좌석은 비활성). 초기 상태는 좌석별 `state`(아래 세부 상태 코드)와 `note`로 정한다.

## 좌석 상태: 3가지 + 세부 상태

| 좌석 상태 | 세부 상태 (★ = 처리 필요 `!`) |
|---|---|
| **빈자리** | 빈자리 |
| **사용중** | 이용 중 · 입실 대기 · 착석(체크인 전) · 잠시 자리 비움 · **짐만 있음** · ★무단 점유 · ★체크인 누락 · ★이탈 · ★사석화 |
| **사용불가** | 고장 · 점검·청소 · 사용 중지 · ★예약 좌석 사용불가 |

세부 상태는 **예약 기록 × 현장 상태(사람 있음/짐만 있음/비어 있음/사용불가) × 관리자 지정**으로 정해진다.

| 예약 \ 현장 | 비어 있음 | 사람 있음 | 짐만 있음 |
|---|---|---|---|
| 없음 | 빈자리 | ★무단 점유 (관리자가 '이용 중' 지정 시 → 이용 중) | ★무단 점유 (관리자가 '짐만 있음' 지정 시 → 짐만 있음) |
| 입실 전 | 입실 대기 | ★체크인 누락 (관리자 지정 시 → 착석(체크인 전)) | ★체크인 누락 |
| 이용 중 | 잠시 자리 비움 → 이탈 기준 초과 시 ★이탈 | 이용 중 | 짐만 있음 → 사석화 기준 초과 시 ★사석화 |

- 예약이 있는 좌석이 사용불가면 ★예약 좌석 사용불가, 체크인 제한을 넘긴 예약은 자동 **미입실** 처리.
- 관리자가 확인해 준 '이용 중'·'짐만 있음'은 그 예약이 끝나면(반납·만료·강제 반납) 함께 풀린다 — 반납 뒤 남은 짐은 무단 점유로 바뀐다.

### 관리자가 좌석에 부여할 수 있는 세부 상태

좌석 상세의 **좌석 상태 지정** 버튼 (카메라 연동 전 임시 배분용):

| 그룹 | 버튼 | 결과 |
|---|---|---|
| 빈자리 | 빈자리 | 현장 비어 있음 |
| 사용중 | 이용 중 · 짐만 있음 | 관리자가 확인한 정상 사용 — **예약이 없어도 처리 필요로 빠지지 않음** |
| 사용중 | ! 무단 점유 · ! 이탈 · ! 사석화 | 기준 시간을 기다리지 않고 바로 처리 필요 (이탈·사석화는 이용 중 예약이 있는 좌석만) |
| 사용불가 | 고장 · 점검·청소 · 사용 중지 | 메모(사유)는 이용자 화면에도 표시 |

### 처리 필요 상황별 조치

| 상황 | 권장 조치 |
|---|---|
| 무단 점유(사람) | 현장 배정 · 퇴실 안내 완료 (예약석이면 예약자를 다른 좌석으로) |
| 무단 점유(짐) | 짐 수거 완료 · 짐 주인에게 배정 |
| 체크인 누락 | 대리 체크인 · 예약자 다른 좌석으로 |
| 이탈 · 사석화 | 강제 반납 · 예약자 경고 |
| 예약 좌석 사용불가 | 다른 좌석으로 이동 · 예약 취소 |
| 미입실 | 경고 후 확인 |

그 밖에 대리 예약·배정, 좌석 이동, 관리자 연장, 경고·이용 정지(경고 3회 이상이면 정지 권장), 처리 이력, 시간대별 이탈·사석화 비율 차트.

## Pi → 웹 계약

`POST /api/detections` · 헤더 `X-Device-Key` · 5초마다 전체 좌석 전송 (CSRF 예외)

```json
{ "camera_id": "cam1", "ts": "2026-09-30T14:03:12+09:00",
  "seats": [ { "seat_no": 1, "occupancy": "person", "since": "2026-09-30T13:40:02+09:00", "confidence": 0.87 } ] }
```

- `occupancy`: `person | item | empty` → 현장 `사람 있음 / 짐만 있음 / 비어 있음`
- 사용불가로 지정된 좌석은 덮어쓰지 않는다. 시계 차이 5초 초과 시 `since` 보정. 모르는 좌석 번호는 `ignored`.
- 서버는 영상·이미지를 받거나 저장하지 않는다.
